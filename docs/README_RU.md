## 🎯 Цель проекта
- **Какую задачу решает:** Демонстрирует способы выполнения длительных задач без блокировки основного (UI) потока в Android.
- **Почему это важно:** Это критически важно для обеспечения плавности интерфейса и предотвращения ошибок "Приложение не отвечает" (ANR).
- **Целевая аудитория:** Разработчики Android и студенты, изучающие фоновую обработку данных.

---

## 📌 Требования к приложению
### Функциональные требования
- Демонстрация зависания интерфейса при выполнении тяжелых задач в основном потоке.
- Выполнение задач в фоне с использованием Java `Thread` и `Handler`.
- Управление параллельными задачами с помощью `ExecutorService` (Single и Fixed thread pools).
- Foreground Service для длительных задач, видимых пользователю (симуляция музыкального плеера).
- Bound Service для взаимодействия между процессами (сервис таймера).
- Современная фоновая работа с `WorkManager` (однократные, периодические, цепочки задач и задачи с ограничениями).
- Демонстрация устаревшего API `AsyncTask`.

### Нефункциональные требования
- **Производительность:** Эффективное использование пулов потоков и ограничений WorkManager.
- **Удобство использования:** Простой интерфейс с логированием и индикаторами прогресса.
- **Надёжность:** Правильная очистка ресурсов в методе `onDestroy`.

---

## 🧠 Общая архитектура
- **Подход:** Простая архитектура на основе Activity для демонстрационных целей.
- **Основные компоненты:**
    - `MainActivity`: Центральная панель управления и логгер.
    - `Services`: `MusicPlayerService` (Foreground), `TimerService` (Bound).
    - `Workers`: Классы `Worker` для `WorkManager` (Download, Unpack, Upload и др.).
    - `AsyncTask`: `MyAsyncTask` для демонстрации устаревших подходов.

## 🧩 UML-диаграмма
Проект включает несколько UML-диаграмм последовательности:

## 🧩 Подробное описание классов

### 📌 Класс: MainActivity
- **Роль:** Главный контроллер интерфейса.
- **Ответственность:** Управление взаимодействием с пользователем, запуск сервисов и постановка задач в очередь.
- **Основные методы:**
    - `onCreate()`: Инициализация представлений, исполнителей и кнопок.
    - `setupButtons()`: Настройка слушателей для всех модулей демо.
    - `log()`: Потокобезопасный метод для вывода логов в интерфейс.
    - `onDestroy()`: Освобождение ресурсов и остановка исполнителей.

### 📌 Класс: MusicPlayerService
- **Роль:** Foreground Service.
- **Ответственность:** Симулирует длительную задачу, которая остается активной даже при сворачивании приложения, требуя уведомления.

### 📌 Класс: TimerService
- **Роль:** Bound Service.
- **Ответственность:** Поддерживает таймер, значение которого Activity может запрашивать во время привязки.

### 📌 Класс: Воркеры WorkManager (SyncWorker, DownloadWorker и др.)
- **Роль:** Единицы фоновой работы.
- **Ответственность:** Выполнение конкретных задач (синхронизация, загрузка, обработка) с гарантией исполнения.

---

## 🔄 Диаграмма работы приложения
1. Пользователь выбирает модуль (Java Threads, Services, WorkManager или Legacy).
2. Нажатие кнопки запускает определенный фоновый механизм.
3. Приложение выводит прогресс на экран, указывая, какой поток выполняет работу.
4. Для сервисов и воркеров обратная связь обеспечивается через системные уведомления или наблюдателей состояния.

## ⚙️ Работа с потоками
- **Используются:** `Thread`, `Handler`, `ExecutorService` (Single & Fixed), `WorkManager`.
- **Почему выбран этот способ:** Чтобы охватить эволюцию многопоточности в Android от базовых потоков Java до современных библиотек Jetpack.
- **Как предотвращаются:**
    - **ANR:** Тяжелые задачи выносятся из основного потока.
    - **Утечки памяти:** В `onDestroy` останавливаются исполнители и отвязываются сервисы. *Примечание: AsyncTask оставлен намеренно для демонстрации возможных утечек.*

---

## 💾 Работа с данными
- **Хранение:** `SaveToDbWorker` симулирует сохранение данных в базу.
- **Корректность:** Использование цепочек WorkManager гарантирует, что сохранение произойдет только после успешной загрузки и распаковки.

---

## 🌐 Работа с сетью
- **Метод:** `DownloadWorker` и `UploadWorker` симулируют сетевые вызовы.
- **Ограничения:** Использование Constraints в WorkManager гарантирует, что сетевые задачи выполняются только при наличии Wi-Fi.
