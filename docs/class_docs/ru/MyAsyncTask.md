# Документация класса MyAsyncTask

## 1. Общая информация
- **Имя класса:** `MyAsyncTask`
- **Тип:** Обычный класс (наследует `AsyncTask`)
- **Назначение:** Этот класс демонстрирует классический (ныне устаревший) способ выполнения фоновых задач в Android. Он используется для запуска короткой задачи (счет от 0 до 100) в фоновом потоке с обновлением `ProgressBar` в главном потоке.
- **Взаимодействие:** Создается и запускается из `MainActivity`. Использует "слабые ссылки" (WeakReferences) на Activity и ProgressBar, чтобы избежать утечек памяти.

## 2. Переменные (Поля класса)
| Имя | Тип | Назначение | Где используется |
| :--- | :--- | :--- | :--- |
| `activityReference` | `WeakReference<MainActivity>` | "Слабая" ссылка на экран приложения. | Для вывода логов и проверки, не закрыт ли экран. |
| `progressBarReference` | `WeakReference<ProgressBar>` | "Слабая" ссылка на индикатор загрузки. | Для обновления полоски прогресса на экране. |

> **Что такое WeakReference?** Представьте, что обычная переменная — это крепкая веревка, которая держит объект. WeakReference (слабая ссылка) — это тонкая ниточка. Если системе нужно очистить память (например, при повороте экрана), она легко рвет эту ниточку, что предотвращает "утечки памяти".

## 3. Методы класса

### Имя метода: `onPreExecute`
- **Тип:** `protected`
- **Возвращаемое значение:** `void`
- **Что делает:** 
    1. Выполняется в **Главном потоке (UI)**.
    2. Делает `ProgressBar` видимым.
    3. Пишет в лог, что задача начинается.
- **Когда вызывается:** Автоматически прямо перед началом фоновой работы.

### Имя метода: `doInBackground`
- **Тип:** `protected`
- **Возвращаемое значение:** `String` (Текст результата)
- **Параметры:** `Void... voids` (Пустые параметры)
- **Что делает:** 
    1. Выполняется в **Фоновом потоке**.
    2. Запускает цикл 100 раз.
    3. В каждом цикле "спит" 50 мс (имитация работы) и вызывает `publishProgress()`.
- **Когда вызывается:** Автоматически после завершения `onPreExecute`.

### Имя метода: `onProgressUpdate`
- **Тип:** `protected`
- **Возвращаемое значение:** `void`
- **Параметры:** `Integer... values` (Текущее число прогресса)
- **Что делает:** 
    1. Выполняется в **Главном потоке**.
    2. Обновляет полоску `ProgressBar` новым значением.
- **Когда вызывается:** Каждый раз, когда в фоновом потоке вызывается `publishProgress()`.

### Имя метода: `onPostExecute`
- **Тип:** `protected`
- **Возвращаемое значение:** `void`
- **Параметры:** `String result` (Результат из `doInBackground`)
- **Что делает:** 
    1. Выполняется в **Главном потоке**.
    2. Скрывает `ProgressBar` и пишет в лог, что задача завершена.
- **Когда вызывается:** Автоматически, когда фоновая работа полностью закончена.

## 4. Жизненный цикл
У `AsyncTask` нет собственного жизненного цикла, как у Activity. Но он **опасен** тем, что может жить дольше, чем экран, который его создал. Если экран закрылся (поворот телефона), а задача еще идет, она может попытаться обновить то, чего уже нет, что приведет к ошибке или "пожиранию" памяти.

## 5. Взаимодействие с интерфейсом (UI)
- **ProgressBar:** Обновляется через `progressBarReference`.
- **MainActivity:** Вывод текста через `activityReference`.

## 6. Взаимодействие с другими компонентами
- **MainActivity:** Активность запускает задачу командой `new MyAsyncTask(this, progressBar).execute()`.

## 7. Общая логика класса
Класс следует шаблону "До -> Во время -> После".
1. **До:** Показать индикатор.
2. **Во время:** Делать "черную работу" в темноте (фоне).
3. **После:** Показать результат и спрятать индикатор.

## 8. Объяснение простыми словами
Представьте, что `MyAsyncTask` — это **Курьер**.
- Вы (Activity) говорите курьеру сходить в магазин (Фон).
- Пока курьер в магазине, он иногда кричит вам: "Я уже купил половину продуктов!" (Обновление прогресса).
- Когда курьер возвращается с пакетами, он отдает их вам лично в руки (Post Execute).

---
**Совет для студента:** `AsyncTask` признан **устаревшим** (Deprecated). Google рекомендует не использовать его в новых проектах. Почему? Потому что им сложно управлять при повороте экрана. Вместо него используйте **WorkManager** или **Kotlin Coroutines**.
