# Документация цепочки Воркеров (Workers)

Этот документ описывает группу классов, используемых для демонстрации **Цепочек работ (Work Chaining)** в WorkManager. Цепочки позволяют выполнять несколько задач в строго определенном порядке (Задача А -> Задача Б -> Задача В).

## 1. Общая информация
Все перечисленные ниже классы наследуют класс `Worker`. Каждый из них отвечает за один конкретный этап в многошаговом процессе.

- **DownloadWorker:** Имитирует скачивание файла из интернета.
- **UnpackWorker:** Имитирует распаковку содержимого из архива.
- **SaveToDbWorker:** Имитирует сохранение извлеченных данных в базу данных.
- **UploadWorker:** Имитирует отправку отчета на сервер (используется с ограничениями).
- **PhotoCompressionWorker:** Отдельная задача, имитирующая сжатие изображения для экономии места.

## 2. Переменные (Поля класса)
Все эти классы в основном используют строку `TAG` для ведения журнала (логов), чтобы мы могли видеть прогресс в Logcat.

## 3. Методы класса (doWork)
Каждый класс реализует метод `doWork()` по схожему шаблону:
1. Пишет в лог, что конкретный этап начался.
2. Использует `Thread.sleep()` (обычно 1-2 секунды) для имитации длительной работы.
3. Возвращает `Result.success()`, что позволяет следующему воркеру в цепочке начать свою работу.

## 4. Взаимодействие и логика
В `MainActivity` эти воркеры связываются следующим образом:
```java
WorkManager.getInstance()
    .beginWith(downloadWork)
    .then(unpackWork)
    .then(saveWork)
    .enqueue();
```
- **Если DownloadWorker упадет с ошибкой:** Система НЕ запустит `UnpackWorker`.
- **Если DownloadWorker завершится успешно:** Система автоматически даст команду на запуск `UnpackWorker`.

## 5. Конкретные роли

### 📌 Класс: `DownloadWorker`
- **Роль:** "Стартер".
- **Логика:** Ждет подключения к сети (если заданы ограничения) и "скачивает" данные.

### 📌 Класс: `UnpackWorker`
- **Роль:** "Обработчик".
- **Логика:** Берет "скачанный" файл и обрабатывает его содержимое.

### 📌 Класс: `SaveToDbWorker`
- **Роль:** "Финализатор".
- **Логика:** Берет обработанные данные и сохраняет их навсегда.

### 📌 Класс: `UploadWorker`
- **Особенность:** Обычно используется с **Ограничениями (Constraints)**. Например, запускается только если телефон на зарядке и подключен к Wi-Fi.

### 📌 Класс: `PhotoCompressionWorker`
- **Роль:** Вспомогательная фоновая задача.
- **Логика:** Уменьшает вес файла для экономии памяти телефона.

## 6. Объяснение простыми словами
Представьте этих воркеров как **Команду в эстафете**.
- **DownloadWorker** — это первый бегун. Он пробегает свой круг и передает палочку **UnpackWorker**.
- **UnpackWorker** не может начать бежать, пока не получит палочку.
- Если один бегун споткнется и упадет (ошибка), гонка остановится, и финишная черта (База данных) так и не будет достигнута.

---
**Совет для студента:** Использование цепочек гораздо лучше, чем запихивание всего кода в один огромный класс. Это делает код понятным, его легче тестировать и исправлять ошибки!
