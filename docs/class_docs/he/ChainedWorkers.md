# תיעוד שרשור עובדים (Chained Workers)

מסמך זה מתאר את קבוצת המחלקות המשמשות להדגמת **שרשור משימות (Work Chaining)** באמצעות WorkManager. שרשור מאפשר להריץ מספר משימות בסדר מסוים (משימה א' -> משימה ב' -> משימה ג').

## 1. מידע כללי
כל המחלקות להלן יורשות את מחלקת ה-`Worker`. כל אחת מהן אחראית על שלב אחד בתהליך רב-שלבי.

- **DownloadWorker:** מדמה הורדת קובץ מהאינטרנט.
- **UnpackWorker:** מדמה חילוץ תוכן מקובץ מכווץ (Zip).
- **SaveToDbWorker:** מדמה שמירת נתונים בבסיס נתונים.
- **UploadWorker:** מדמה שליחת דוח לשרת (בשימוש עם אילוצים).
- **PhotoCompressionWorker:** משימה עצמאית המדמה הקטנת נפח תמונה.

## 2. משתנים (שדות המחלקה)
כל המחלקות הללו משתמשות בעיקר במחרוזת `TAG` לצורך כתיבת הודעות התקדמות ל-Logcat.

## 3. מתודות המחלקה (doWork)
כל מחלקה מממשת את המתודה `doWork()` בצורה דומה:
1. כותבת ללוג שהשלב הספציפי התחיל.
2. משתמשת ב-`Thread.sleep()` (בדרך כלל 1-2 שניות) כדי לדמות עבודה ממושכת.
3. מחזירה `Result.success()` כדי לאפשר לעובד הבא בשרשרת להתחיל.

## 4. אינטראקציה ולוגיקה
ב-`MainActivity`, העובדים הללו מקושרים כך:
```java
WorkManager.getInstance()
    .beginWith(downloadWork)
    .then(unpackWork)
    .then(saveWork)
    .enqueue();
```
- **אם DownloadWorker נכשל:** המערכת לא תפעיל את `UnpackWorker`.
- **אם DownloadWorker מצליח:** המערכת תפעיל באופן אוטומטי את `UnpackWorker`.

## 5. תפקידים ספציפיים

### 📌 מחלקה: `DownloadWorker`
- **תפקיד:** ה"מתניע".
- **לוגיקה:** מחכה לחיבור רשת (אם הוגדרו אילוצים) ו"מוריד" נתונים.

### 📌 מחלקה: `UnpackWorker`
- **תפקיד:** ה"מעבד".
- **לוגיקה:** לוקח את הקובץ ה"מורד" ומעבד את התוכן שלו.

### 📌 מחלקה: `SaveToDbWorker`
- **תפקיד:** ה"מסיים".
- **לוגיקה:** לוקח את הנתונים המעובדים ושומר אותם לצמיתות.

### 📌 מחלקה: `UploadWorker`
- **מאפיין מיוחד:** בדרך כלל בשימוש עם **אילוצים (Constraints)**. למשל, הוא ירוץ רק אם הטלפון בטעינה ומחובר ל-Wi-Fi.

### 📌 מחלקה: `PhotoCompressionWorker`
- **תפקיד:** כלי עזר ברקע.
- **לוגיקה:** מקטין את משקל הקובץ כדי לחסוך מקום בזיכרון הטלפון.

## 6. הסבר במילים פשוטות
חשבו על העובדים הללו כעל **נבחרת במרוץ שליחים**.
- **DownloadWorker** הוא הרץ הראשון. הוא רץ את הסיבוב שלו ומעביר את המקל ל-**UnpackWorker**.
- **UnpackWorker** לא יכול להתחיל לרוץ עד שהוא מקבל את המקל.
- אם אחד הרצים מועד ונופל (נכשל), המרוץ נעצר, וקו הסיום (בסיס הנתונים) לא יושג לעולם.
